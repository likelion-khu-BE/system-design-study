# 주변 친구

인근의 친구 목록을 보여주는 시스템(사용자의 위치 정보 변경 내역을 그 친구에게 전달하는 시스템)

기능적 요구사항: 주변 친구 목록 표시, 갱신
비기능 요구사항: 낮은 지연 시간, 안정성, 결과적 일관성

규모 추정: 주변 친구는 5마일, 30초 주기 갱신, QPS = 334,000

### 개략적 설계

로드 밸런서 - API 서버와 웹소켓 서버 앞단에 위치

API 서버 - 요청/응답 트래픽 처리

**웹소켓 서버**
- 클라이언트와 서버 사이 실시간 통신
- 각 클라이언트 한 대와 웹소켓 연결 지속적 유지

레디스 위치 정보 캐시 - 가장 최근 위치 캐시 + TTL

사용자 데이터베이스 - 사용자 정보, 친구 관계 정보 저장

위치 이동 이력 데이터베이스 - 위치 변동 이력 보관

**레디스 펍/섭 서버**
- 한 사용자의 위치 정보 변경 내역 모든 친구에게 전달하는 라우팅 계층
- 사용자마다 채널이 존재(그 채널이 바로 레디스 펍/섭), 채널은 구독 관계의 친구들을 연결

### 주기적 위치 갱신

클라이언트 위치 변경 사실 로드 밸런서에 전송 → 웹소켓 서버로 보내짐 → 위치 이동 이력 데이터베이스에 저장, 새 위치 캐시에 보관, 해당 사용자 채널에 새 위치 발행 (병렬 수행) → 모든 온라인 상태 친구들에게 브로드캐스트 됨 → 거리 새로 계산

사용자 아래에 연결 유지하고 있는 웹소켓 서버, 그 아래에 사용자 전용 채널(레디스 펍/섭), 그 아래에 또 구독자들(친구 관계)의 웹소켓 서버, 그 아래에 구독자들(사용자) 클라이언트

### 규모 확장

**API 서버**

무상태 서버, 확장 방법 다양

**웹소켓 서버**

유상태 서버, 제거할 때 주의 필요
좋은 로드 밸런서가 있어야 함

**클라이언트 초기화**

초기화 작업 과정에서 친구의 활성화/비활성화 상태에 관계없이 모든 친구 채널 구독하고 모든 친구에게 현재 위치 전송

**사용자 데이터베이스**

관계형 데이터베이스 샤딩 → 수평적 규모 확장 가능

**위치 정보 캐시**

TTL 사용자 위치 정보 갱신 될 때마다 초기화, 샤딩으로 부하 고르게 분배

**레디스 펍/섭 서버**

오프라인 사용자 존재, 이후에 CPU 자원을 사용하지 않음 → 이를 이용!
모든 사용자에 채널 하나씩 부여, 친구의 상태는 중요하지 않음 → 설계 단순해짐

**분산 레디스 펍/서버 클러스터**

모든 채널은 서로 독립적, 사용자 ID를 기준으로 펍/섭 서버 샤딩

서비스 탐색 컴포넌트 도입 - 해시 링


해시 링: 웹소켓 서버 - 1. 메시지 발행할 펍/섭 서버 선정 2. 해당 서버가 관리하는 사용자 채널에 위치 정보 변경 내역 발행

#### **레디스 펍/섭 서버 클러스터 규모 확장 고려사항**

레디스 펍/섭 서버 클러스터는 유상태 서버 클러스터로 취급
어느 정도 여유를 두고 오버 프로비저닝

클러스터 크기 어떻게 조정? - 새로운 링 크기 계산, 새로운 내용으로 갱신, 대시보드 모니터링

#### 펍/섭 서버 새 서버로 교체

교체 되는 서버의 채널만 건든다. 장애가 발생한 노드를 대기 중인 노드와 교체

### 주변 임의 사용자

지오해시 이용, 격자마다 채널을 하나씩 만들어 둔다.

### 얼랭(레디스 펍/섭 대안)

경량 프로세스. 생성 비용 엄청나게 저렴. 분산 쉬움. 운영 부담 낮음. 도구들 굿. 배포 도구 강력.

웹소켓 서비스 - 얼랭, 레디스 펍/섭 클러스터 - 분산 얼랭 애플리케이션, 각 사용자 - 얼랭 프로세스

### 새롭게 알게 된 개념

- QPS(Query per Second) - 서버나 데이터베이스가 1초 동안 처리할 수 있는 요청(쿼리)의 수, 시스템의 처리 용량과 성능을 측정하는 단위
- 샤딩 - '샤드(Shard)'라는 작은 단위의 여러 독립된 데이터베이스 서버로 수평 분할하여 분산 저장하고 관리하는 기술
- 항구적 통신 - 클라이언트와 서버가 한 번 연결을 맺은 후, 이를 끊지 않고 계속 유지하며 데이터를 주고받는 통신 방식
- 레디스 - 메모리를 기반으로 데이터를 빠르게 처리하는 고성능 키-값(Key-Value) 데이터 저장소, 위치 데이터의 빠른 읽기/쓰기 지원
- 오버 프로비저닝 - 실제 필요한 것보다 더 많은 컴퓨팅 자원(CPU, 메모리, 스토리지, 네트워크 대역폭 등)을 미리 할당해 두는 것
- 유상태/무상태 - 서버가 클라이언트의 상태를 보존 / 서버가 클라이언트의 상태를 보존하지 않음
