 5000개 호텔, 100만개 객실
 평균 70% 객실 사용중, 평균 3일 투숙
 일일 예상 예약 : 240000
 초당 예약 건수 : 3

## 관계형 DB를 선택한 이유

 읽기가 쓰기보다 많음
 ACID 보장 : ACID는 앞서 말했던 예약 트랜잭션을 DB 단위에서 보장하게 도와주는 도구다
 모델링이 쉽다 : 호텔, 객실, 투숙객 이들 사이 관계도가 명확함

## MSA 채택 이유

책에서 MSA를 고른 이유를 설명하진 않지만,
호텔 서비스 / 요금 서비스 / 예약 서비스 등
비즈니스 모델이 명확하게 나뉘고, 장애 격리, 배포 독립성 측면을 고려한 선택이라 볼 수 있다.

> 호텔 예약 시스템은 조회와 예약이 빈번하게 일어난다

## 조회와 예약이 다른 점

 조회 : DB를 읽기만 함, 같은 걸 같이 봐도 상관 x
 예약 : DB의 데이터를 변경함, 서로 같은 데이터를 동시에 변경할 위험성 => 트랜잭션 필요

## 예약 트랜잭션 동작

1. 그 날짜에 남은 객실이 있는지 확인
2. 남은 객실 수를 차감
3. 예약 레코드를 생성
4. 결제 처리

> 4가지 동작이 하나로 묶여야만 한다.

## 동시성 문제 상황

이번 절에선 빈번하게 발생하는 트랜잭션 요청 사이에서, 어떻게 고객의 경험과 안정성을 확보할 수 있는지에 대해 얘기한다.

### 1. 동일한 사용자의 같은 예약 여러번 문제

멱등키는 각 예약 시도에 대한 고유 ID로 이미 처리한 요청인지 판별 가능

### 2. 다른 사용자들이 같은 방을 동시에 예약 문제

다른 사용자의 경우 트랜잭션1이 완료되지 않은 시점에서 트랜잭션2가 동작할 가능성이 있다.
같은 자원을 두고 경쟁하는 상황이므로 락, DB 제약조건을 활용해 해결해본다.

### 2-1. 비관적 락 VS 낙관적 락

 비관적 락 : 수정하기 전에 미리 잠금
 낙관적 락 : 잠그지 않다가 저장하는 순간 충돌을 검사

### 2-2. DB 제약 조건

낙관적 락이 저장하는 순간 충돌을 검사하는 것과 동일하게, 데이터베이스에서 수정 작업을 진행하고 DB에 업데이트 하는 순간 조건문을 통해 유효성을 검사해, 제약 조건 위반시 트랜잭션을 롤백하는 방식이다.

비관적 락은 충돌을 강력하게 막지만 대기시간이 길어진다.
(낙관적 락 || DB 제약 조건)은 자원 경쟁 시도 자체는 허용해 대기 시간이 짧다, 하지만 사용자 입장에서 시도 후 예약 실패 메세지를 전달받게 될 것이다.
데이터 자원 경쟁이 심한 경우엔 비관적 락을, 그렇지 않다면 (낙관적 락 || DB 제약 조건)이 적합하다. QPS가 높지 않은 예약시스템의 경우 낙관적 락을 선택한다

## 규모가 커질 때 데이터베이스 부하를 감당하는 방법

 데이터베이스를 샤딩한다.
 과거 기록은 별로 중요하지 않으므로 냉동 창고로 보낸다.
 캐시를 도입한다.

### 캐시

과거 기록은 중요하지 않은 특성을 고려하여
적절한 TTL을 설정해 자동 소멸되게 한다. & 메모리가 차면 오래 안 쓴 것부터 내보내는 LRU 기술을 사용한다. Redis는 두가지 기능을 지원하여 메모리를 최적으로 활용하기 적합하다.
읽기는 캐시, 쓰기는 DB로 역할을 나눠 DB 부하를 줄일 수 있다.

### DB와 캐시의 비동기성

DB에 먼저 쓰면 변경 내역을 읽는 소스 커넥터를 통해 캐시에 반영되게 한다.
이 반영되는 지연시간 동안 클라이언트는 예약된 객실을 예약 시도하는 경우가 발생해 사용자 경험이 떨어질 수 있다.

## MSA에서 독자적인 DB에 걸친 일관성 문제를 해결하는 방법

MSA는 독자적으로 배포되는 서비스 단위로 각각 독자적인 DB를 갖는다.
DB의 ACID 속성이 개별적으로 적용되지만 여러 DB에 걸쳐 실행되지 못한다.

### 2PC(2단계 커밋)

1. 1단계 코디네이터가 트랜잭션에 포함할 DB 모두에게 prepare 준비를 요청, 각 DB들은 락을 걸고 코디네이터에게 응답한다.
2. 2단계 각 DB들의 prepare 응답이 왔다면 코디네이터는 commit 지시를 내린다. DB들 중 하나라도 실패할 시 모든 DB 작업을 롤백 시킨다.

### Saga

트랜잭션들을 순차적으로 실행시킨다. T1 => T2 => T3.
트랜잭션 실패시 역으로 보상 트랜젝션을 실행시킨다. T1 <= T2 <= T3

### 하이브리드 (완벽한 MSA를 포기하고 DB를 공유해버림)

서비스 독립성을 포기하고 (각 서비스의 독립적인 확장성 감소, 장애 격리 감소)
단일 DB에서 ACID 기반 동시성 처리를 통해 시스템 복잡성을 낮춘다.
