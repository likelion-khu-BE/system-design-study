# 6장 광고 클릭 이벤트 집계


## 1. 광고 클릭 수 세는 게 왜 어려울까?

돈이 걸려 있으므로 정확해야 하고, 양이 많아 서버 여러 대로 나누어야 하고, 빨라야 함
| 조건 | 숫자 |
| --- | --- |
| 정확해야 함 | 클릭 수 = 광고주한테 청구하는 돈 |
| 양이 많음 | 하루 10억 건, 피크 때 초당 5만 건 |
| 빨라야 함 | 클릭 후 몇 분 안에 결과가 나와야 함 |


## 2. 원본이랑 집계 결과를 왜 둘 다 저장해?

뻑났을 경우 원본을 참고해야 함. 집계 결과만 있으면 숫자가 틀렸을 때 고칠 방법이 없다.

근데 원본만 있으면 조회할 때마다 10억 건을 세야 해서 느림


## 3. 읽기보다 쓰기가 많다는 게 무슨 뜻이야?

광고 클릭 이벤트는 읽기보다 쓰기가 많음

- 쓰기: 광고 클릭할 때마다 저장 → 초당 1만~5만 건
- 읽기: 광고주가 클릭 수 조회할 때만 → 초당 수백 건


## 4. 클릭은 어떤 길로 흘러가?

```
클릭 로그 수집 (서버에 쌓인 클릭 로그를 읽어서 큐로 보냄)
    ↓
큐 ① (원본 클릭 이벤트, 피크 초당 5만 건을 받아둠)
    ↓                          ↘
집계 서비스 (큐 ①에서 꺼내서 카운트)   원시 데이터 DB (원본 보관)
    ↓
큐 ② (집계 결과)
    ↓
DB 기록기 → 집계 DB에 저장
    ↓
질의 서비스 (조회 요청에 집계 DB로 응답)
```


## 5. 초당 5만 건을 서버 여러 대가 어떻게 나눠 세?

서버 한 대가 다 셀 수 없어서 맵 → 집계 → 리듀스로 나눔 (제친구한테쉽게설명해달라고햇어요)

```
들어온 클릭: A, B, A, C, D, A, C, B, D, D, D
```

1. **맵 노드**: 광고 ID 보고 담당 집계 노드로 보낸다. 세지는 않는다.

```
집계 노드 1 (A, B 담당): A, B, A, A, B
집계 노드 2 (C, D 담당): C, D, C, D, D, D
```

2. **집계 노드**: 자기 담당 광고만 센다.

```
집계 노드 1: A = 3, B = 2  → 내 Top 2: [A 3, B 2]
집계 노드 2: C = 2, D = 4  → 내 Top 2: [D 4, C 2]
```

3. **리듀스 노드**: 후보를 모아서 최종 결정한다.

```
최종 Top 2: [D 4, A 3]
```
TOP 100은 마지막에 합침

## 6. 클릭 시각은 언제를 기준으로 해?

처리 시간이나 클릭 발생 시간 두 개 중에 발생 시각을 기준으로 함

처리 시간으로 하면 안 되는 이유: 서버 상태에 따라서 결과값이 달라지고.. 돈 문제에 에민해짐.

## 7. 늦게 도착한 클릭은 어떻게 해?

늦게 도착한 클릭은 일정 시간 기다려주는 워터마크로 처리함


## 8. "1분 동안"은 어떻게 잘라?

텀블링: 정확하게 딱딱 끊는다. 슬라이딩: 겹치는 구간이 존재한다. 텀블링은 클릭 1건이 한 구간에만 들어가고 슬라이딩은 여러 개에 들어간다.

```
클릭: 12:00:10 A / 12:00:50 A / 12:01:20 B / 12:01:30 B / 12:01:40 B

텀블링 (1분씩 끊음)
[12:00:00 ~ 12:01:00)  A=2
[12:01:00 ~ 12:02:00)  B=3

슬라이딩 (1분 길이, 30초마다 이동)
[12:00:00 ~ 12:01:00)  A=2
[12:00:30 ~ 12:01:30)  A=1, B=1   ← 12:00:50 A가 두 구간에 들어감
[12:01:00 ~ 12:02:00)  B=3
```


## 9. 서버가 죽었다 살아나면 두 번 세지 않을까?

큐를 두 개 이용하는 방법을 사용한다. 1. 결과를 저장 2. 어디까지 저장했는지(오프셋)를 저장.

그런데 1은 디비, 2는 카프카라서 한 번에 묶을 수가 없다. 1도 큐에 넣게 되면 1+2를 트랜잭션으로 한 동작으로 묶을 수 있게 된다.


## 10. 클릭이 더 많아지면?

클릭이 전체적으로 많아지는 거랑 핫스팟은 다른 문제임

- 전체 클릭이 많아짐: 큐 파티션, 집계 노드, 디비 서버를 늘려야 함
- 핫스팟: 광고를 여러 노드에 나누어서 세고 합쳐야 함


## 11. 계산이 틀렸으면?

계산이 틀렸으면 재계산이나 대조를 이용한다

- 재계산: 원본 데이터를 읽어서 다시 셈
- 대조: 마지막에 배치로 다시 세서 실시간으로 센 결과랑 비교함
